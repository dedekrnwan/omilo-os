# P5b — Role-3 MCP Exposure (external clients) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let external MCP clients (Claude Desktop, Cursor, ChatGPT) drive omilo's agents through a revocable, scope-limited `McpAccessToken` that acts-as one Helper — reusing the entire Role-2 server (tools, gate, autonomy, SafetyLimits, audit) so an external caller can never exceed that Helper's envelope.

**Architecture:** Role-3 adds a thin auth + scoping layer in front of the existing Role-2 dispatch. A new tenant `McpAccessToken` (hashed, scoped to a Helper + a `scopes` set, revocable, expirable) authenticates a new external JSON-RPC endpoint `POST /v1/x/mcp`. That endpoint resolves company+helper+scopes from the token, then calls the SAME `dispatch()` the per-agent server uses — but filters `tools/list` and gates `tools/call` to the token's scopes, updates `last_used_at`, and audits each call as `ToolCall` with `actor="external:<label>"`. Side-effecting actions still become Proposals via the existing gate using the Helper's `autonomy_cap`. The WSS gateway host (`mcp.omilo.app/x/{company}`) is deployment/transport and out of scope; this plan ships the HTTP JSON-RPC surface that a gateway proxies to.

**Tech Stack:** FastAPI, SQLAlchemy 2.0, Postgres 16 + RLS, Pydantic v2, hashlib/secrets. Builds on merged P0–P5a (`main @ 4ba9602`).

**Spec:** docs/technical/11-marketplace-connectors-mcp.md §6 (Role-3), §7.4 (Connections UI), §8 (API surface); docs/technical/05-mcp-surfaces.md (Role-2 reused wholesale); docs/technical/01-data-model.md §12.3 (McpAccessToken).

## Global Constraints

- Builds on merged P0–P5a; branch off fresh `main` (`4ba9602`). Suite is **580 green** — never regress it.
- Reuse the P2 Role-2 server wholesale: `apps/api/omilo/mcp/server.py` (`_run_tool`, the JSON-RPC shape, the `SET LOCAL ROLE omilo_app`+`set_company` dispatch session, `ToolCall` logging) and `omilo/mcp/tools.py` (`dispatch(tool_name, arguments, db, helper) -> (result, decision)`, `TOOL_CATALOG`, `get_connector_tools_for_helper`). Do NOT fork the dispatch or the gate — call them.
- **An external token can NEVER exceed its Helper's envelope.** The gate already derives `effective_autonomy(workspace, None, helper.autonomy_cap)`; Role-3 passes the SAME resolved Helper, so side-effecting calls still produce Proposals and `autonomy_cap`/SafetyLimits still bind. Scopes only ever *narrow*, never widen.
- `McpAccessToken` is a tenant table — reuse the P0 RLS pattern EXACTLY (`omilo_app` grants + ENABLE + FORCE RLS + `tenant_isolation` policy). The token secret is hashed (`sha256`), stored as `token_hash`; the raw token is shown once at mint and never recoverable (mirror `Helper.mcp_token_hash` minting in server.py).
- Revocation + expiry are enforced on EVERY external call: a token with `revoked_at` set or `expires_at` in the past → 401, before any tool runs. `last_used_at` is updated on each successful auth.
- Every external tool call is audited: `ToolCall.actor = "external:<token_label>"` (add an `actor` column to ToolCall, additive, default "agent" for existing agent calls). Propose-don't-act and all existing decisions (`allowed|proposal|refused|error`) are unchanged.
- Offline-deterministic tests only: no network; mint a token via the endpoint, call `/v1/x/mcp` with it, assert against seeded data. Mirror `tests/test_mcp.py` fixtures (`_sign_up_in`, `_rpc_payload`, tenant/superuser session helpers).

## Review Focus

- **Revoked/expired token still works:** a call with a revoked or expired `McpAccessToken` must 401 before any tool executes (no data read, no Proposal, no ToolCall-as-success). Test: revoke → call → 401; expire → call → 401. (T3)
- **Scope escalation:** a token scoped to `["goals"]` must NOT be able to call `flows_list`, `propose`, or any connector tool — `tools/list` hides them and `tools/call` returns an error, with a ToolCall logged `decision="refused"`. Test: goals-only token calls flows_list → error, not data. (T3)
- **Autonomy cap not exceeded via external path:** an external token whose Helper has `autonomy_cap="ask"` calling a consequential `propose` must produce a Proposal (needs_owner), never auto-execute — identical to the Role-2 result. Test: external propose on an ask-capped helper → `status:"proposed"`. (T3)
- **Cross-tenant token:** company A's token can only ever see/act on company A (helper resolved from the stored token's `company_id`, dispatch under that company's RLS). Test: A's token, B's data invisible. (T2/T3)
- **Token collision / malformed:** absent, malformed, or unknown-hash bearer → 401; two tokens never collide (random secret). Test: garbage bearer → 401. (T3)

### Task 2: Mint / list / revoke endpoints

**Files:**
- Create: `apps/api/omilo/api/mcp_tokens.py`
- Modify: `apps/api/omilo/main.py` (wire router)
- Test: `apps/api/tests/test_mcp_tokens_api.py`

**Interfaces:**
- Consumes: T1 `McpAccessToken`; the token-hash idiom from `omilo/mcp/server.py` (`_mint_raw_token`/`sha256`); Helper model.
- Produces (per spec §8, company-scoped via the tenant dep, admin/owner guard on mint/revoke like other privileged routes):
  - `POST /v1/mcp-access-tokens {label, helper_id, scopes[], expires_at?}` → mint: validate the helper belongs to the company; generate a raw secret (`secrets.token_urlsafe(32)`), store `token_hash=sha256(raw).hexdigest()`; return `{id, label, helper_id, scopes, token: "<raw>", created_at}` — the raw `token` is returned ONCE and never again.
  - `GET /v1/mcp-access-tokens` → list the company's tokens WITHOUT the secret: `{id, label, helper_id, scopes, expires_at, last_used_at, revoked_at, created_at}` + an `active` boolean.
  - `DELETE /v1/mcp-access-tokens/{id}` → set `revoked_at=now` (soft revoke, keeps audit); idempotent (re-revoke returns ok). 
- The raw token format is a single opaque secret (NOT `helper_id.secret` — Role-3 tokens resolve the helper from the stored row, not from the token body).

### Task 3: External MCP endpoint — auth, scope filtering, enforcement, audit

**Files:**
- Create: `apps/api/omilo/mcp/external.py` (`POST /v1/x/mcp` + `verify_access_token` + `SCOPE_TOOLS`)
- Modify: `apps/api/omilo/main.py` (wire router)
- Modify: `apps/api/omilo/mcp/server.py` ONLY if a small refactor is needed to reuse `_run_tool`/dispatch without duplication (prefer importing; if `_run_tool` is too helper-token-coupled, extract the inner "open tenant session → dispatch → log ToolCall" into a shared function both endpoints call, passing `actor`).
- Test: `apps/api/tests/test_mcp_external.py`

**Interfaces:**
- Consumes: T1 `McpAccessToken`, T2 mint endpoint (tests mint via it), Role-2 `dispatch(tool_name, arguments, db, helper)`, `TOOL_CATALOG`, `get_connector_tools_for_helper`, `set_company`, `ToolCall`.
- Produces:
  - `SCOPE_TOOLS: dict[str, set[str]]` — maps a scope name → the native tool names it unlocks. Binding map: `"identity"`→{whoami} (whoami is ALWAYS allowed regardless of scopes); `"goals"`→{goals_list}; `"routines"`→{routines_list}; `"flows"`→{flows_list}; `"docs"`→{recall, remember}; `"skills"`→{skills_list, skill_read, skill_save, skill_publish}; `"propose"`→{propose}; `"connectors"`→(all compiled connector tools for the helper). A token's allowed tool set = union of its scopes' tools ∪ {whoami}.
  - `verify_access_token(raw: str, *, now) -> McpAccessToken | None` — hash the raw, look it up via a privileged session (across tenants, like `_verify_token`), return the row only if `is_active(now)`; else None. Updates `last_used_at` (best-effort).
  - `POST /v1/x/mcp` — Bearer `McpAccessToken`. Verify → 401 if absent/malformed/unknown/revoked/expired. Resolve the acted-as Helper + company from the token row. Then:
    - `tools/list` → the Role-2 catalog + connector tools, FILTERED to the token's allowed set (whoami always included). Never list a tool the scopes don't grant.
    - `tools/call {name, arguments}` → if `name` not in the allowed set → return a JSON-RPC error (code for "not permitted") AND log a `ToolCall(decision="refused", actor="external:<label>")`; else open the company-scoped session and call `dispatch(name, arguments, db, helper)` (the SAME path Role-2 uses — so the gate + autonomy_cap + SafetyLimits bind), log `ToolCall` with `actor="external:<label>"` and the returned decision.
  - Wire router into main.py.

## Self-Review notes (author)

- **Spec coverage:** §6 Role-3 (acts-as helper, reuses Role-2, token-scoped, same safety envelope, revocable/observable) → T1 model + T3 endpoint/enforcement; §8 API (list/mint/revoke) → T2; §7.4 Connections UI is frontend (P5d) — backend provides the list/active/last_used fields it needs (T2). Deliberately deferred: the WSS transport host (`mcp.omilo.app/x/{company}`) is deployment — T3 ships the HTTP JSON-RPC surface a gateway proxies to; noted in docs.
- **Reuse, not fork:** the single most important design rule — T3 calls Role-2 `dispatch()`; it adds auth + scope-filter + actor audit only. If `_run_tool` is too coupled to helper-tokens, extract one shared `run_tool_for(helper, name, args, actor)` and have BOTH endpoints use it (keeps the gate/ToolCall logic single-sourced). The autonomy-cap-not-exceeded property falls out of reuse for free.
- **Security posture:** scopes only narrow; whoami always allowed; revoked/expired → 401 before any effect; hashed token, raw-once; soft-revoke keeps audit. The Review Focus pins revoked/expired, scope-escalation, autonomy-cap, cross-tenant, and malformed — the five ways an external surface bites.
- **Type consistency:** `McpAccessToken.is_active(now)` used by both T2 (`active` field) and T3 (auth gate). `SCOPE_TOOLS` is the single source of scope→tool mapping. `ToolCall.actor` added in T1, written in T3.
- **Proportion:** 3 tasks — schema, CRUD, the external endpoint+enforcement. The endpoint task carries the security weight and the bulk of the tests.
